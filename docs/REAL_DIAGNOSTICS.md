# Real global diagnosis and bounded local optimization

Development preview. Native compilation, protocol tests and live acceptance must be reported separately. Do not infer a usable performance improvement from a synthetic test or a receipt alone.

The primary SD menu now collects a real snapshot locally. After an explicit data preview, it sends the approved fields to the user's dot through the existing private foreground Tunnel. The runtime must be in the separately approved global-diagnostics scope. The app does not read credentials, create a login service, start the runtime or expand its permissions.

## Bounded data

A one-shot two-point sample reads at most4096 visible process counters over approximately2seconds. The payload contains the union of the top5CPU and top5resident-memory consumers, up to5 eligible ordinary GUI app targets, and coverage counts. The app never sends PID, process start identity, bundle/executable path, signature, argv, environment, document/window title or credentials. Only recognized ordinary GUI app display names are shared; protected/system/helper/unknown process rows use fixed category labels. Main-process CPU/RSS is not an app-group total and inaccessible processes are explicitly missing.

Host CPU/RAM values come from existing60second collectors; capacity from the300second collector; current I/O from the restored1second disk display reader. Each value carries its actual observation time. Up to5 recent CPU/memory points within5minutes provide limited context, not a sustained-fault guarantee. No duplicate host collectors are introduced. No real data leaves the device before the preview confirmation.

## Approved capabilities

The cloud may recommend one normal quit of an eligible opaque app target,60seconds of local observation, or no action. The plan is bound to immutable request bytes, hashes, target and expiry. Returned prose is untrusted plain text and cannot authorize execution.

A quit requires a second local approval showing the actual app, current usage, effect and save-work warning. The local executor rechecks the same cloud plan, PID/kernel process start/UID/bundle/code identity and a fresh2second measurement. Candidates must still consume at least25% of one CPU core or512MiB resident memory. Eligible apps are signed ordinary GUI apps in Applications; system apps, this monitor, ChatGPT/Codex, terminals, runtime-related apps, unsigned apps and background processes are excluded.

Exactly one `NSRunningApplication.terminate()` request is allowed. A save prompt, refusal or15second timeout stops the attempt. No `forceTerminate`, signal, shell, AppleScript or automatic retry is used. The user handles any app save prompt. Cancelling after dispatch cannot retract that OS request.

When exit is confirmed, existing host metrics are observed for60seconds. The receipt reports actual exit confirmation, timestamps, missing/stale data and before/after values. Identical timestamps are the same cache entry. A metric difference is not proof of causation, freed-memory amount or lasting improvement. The bounded receipt can be returned to the same dot under the initial data-sharing confirmation; runtime receipt acknowledgement is verified by exact hash. The cloud receives client-reported evidence, not cryptographic proof of execution.

Pending plans and approvals are never resumed after restart. Owner-private receipts retain at most20 entries for7days. Interrupted or cancelled attempts preserve any effect already requested. No local process has been quit during cloud development; the app must still pass a separately authorized native acceptance run.

## Disk display fix

The upstream ActivityReader is restored independently from capacity/SMART/process readers. I/O rates use actual monotonic elapsed time. First samples, missing counters, rollback, long gaps, pause and sleep/wake reset the baseline. Capacity stays300seconds, I/O display1second, SMART/process disk probes and raw reader/widget persistence remain disabled.
